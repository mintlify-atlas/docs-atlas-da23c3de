A shim is a small wrapper script that mntpack writes into `~/.mntpack/bin/` (or `$MNTPACK_HOME/bin/`). When you add that directory to your PATH, every globally-installed tool becomes available as a plain shell command — without copying binaries to system directories or modifying anything outside of `~/.mntpack/`. This page explains how shims are created, how they resolve their targets, and how the `autoUpdateOnRun` setting changes their runtime behaviour.

## Creating a Global Shim

Pass `-g`/`--global` to `sync` (or any of its aliases) to create a shim in addition to installing the package:

```bash
mntpack sync MINTILER-DEV/scalf -g
mntpack add  owner/repo --name mytool --global
```

Without `-g`, the package is installed and tracked but only accessible via `mntpack run <package>`. With `-g`, a shim script is written so you can call the tool directly.

## Shim Location and PATH Setup

Shims are always written to:

```text
<MNTPACK_HOME>/bin/
```

which defaults to `~/.mntpack/bin/` when `MNTPACK_HOME` is not set. The installer adds this directory to your PATH automatically. If you are setting up manually, add it yourself:

```bash
# bash / zsh
export PATH="$HOME/.mntpack/bin:$PATH"

# fish
fish_add_path ~/.mntpack/bin
```

## Platform-Specific Shim Format

mntpack writes different shim formats depending on the operating system:

<Tabs>
  <Tab title="Unix (shell script)">
    On Linux and macOS, shims are POSIX shell scripts. They resolve the mntpack home directory at execution time via `MNTPACK_HOME`, then either call `mntpack run` or execute the binary directly depending on the `autoUpdateOnRun` config.

    ```sh
    #!/bin/sh
    # generated by mntpack — do not edit
    exec mntpack run mytool -- "$@"
    ```
  </Tab>
  <Tab title="Windows (.cmd batch)">
    On Windows, shims are `.cmd` batch files. They use delayed expansion to correctly propagate the exit code of the wrapped process:

    ```bat
    @echo off
    setlocal enabledelayedexpansion
    mntpack run mytool -- %*
    exit /b !errorlevel!
    ```

    Delayed expansion is essential here: without it, `%errorlevel%` is evaluated before the command runs, giving incorrect exit codes back to the calling process.
  </Tab>
</Tabs>

## How Shims Resolve Their Target

Shims do not hardcode absolute paths to binaries. Instead they rely on `MNTPACK_HOME` (or the default `~/.mntpack`) being accessible at runtime. This means:

- Moving or renaming the mntpack home directory (and updating `MNTPACK_HOME`) automatically redirects all shims.
- Shims continue to work if the binary is rebuilt or updated in the store, since the resolution happens through `mntpack run` or through the current package record rather than a frozen path.

## autoUpdateOnRun: Two Shim Modes

The `autoUpdateOnRun` config key controls what a shim does when invoked:

<CardGroup cols={2}>
  <Card title="autoUpdateOnRun: false (default)" icon="bolt">
    The shim executes the package binary directly from the store. Fast, no network call. Binary must already be built and present.
  </Card>
  <Card title="autoUpdateOnRun: true" icon="arrows-rotate">
    The shim calls `mntpack run <package>`, which syncs the repository first and triggers a lazy build if needed before launching. Always runs the latest version.
  </Card>
</CardGroup>

Configure it with:

```bash
mntpack config set autoUpdateOnRun true
```

When `autoUpdateOnRun` is `false` and a binary is not yet materialized (e.g. after a bare `sync` without `-g` plus a subsequent global shim install), `mntpack run` will perform the lazy build on first execution.

## Shim Naming

The name of the shim file determines what command you type in your terminal. mntpack resolves shim names as follows:

- **Rust projects** — reads the `[package] name` field from `Cargo.toml`. Hyphens in the package name are converted to underscores in the executable name (Rust's default convention), and that name becomes the shim. For example, a crate named `my-tool` produces a shim called `my_tool`.
- **`bin` command-map** (`mntpack.json`) — the key of each entry in the `bin` object becomes a shim name. For example, `{ "phc": "php phc.php" }` creates a shim named `phc`.
- **All other projects** — the package name is used as the shim name.

## Listing Global Shims

To see which packages have global shims and what commands they expose:

```bash
mntpack list --global
```

To find which package provides a specific command:

```bash
mntpack which phc
```

## Removing a Shim

Removing a package also removes its shim:

```bash
mntpack remove scalf
# or any alias: uninstall, rm, unsync
```

The shim file is deleted from `~/.mntpack/bin/` as part of the removal process.

<Warning>
If you manually delete a binary from the store without going through `mntpack remove`, the shim will remain but will fail to execute. Run `mntpack doctor --fix` to detect and repair broken shim references.
</Warning>
